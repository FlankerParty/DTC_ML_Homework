# 机器学习分类：客户流失预测（Churn Prediction）

> 本章以电信客户流失预测为例，整理二分类任务中最常见的一套机器学习流程。重点保留理论、公式、特征重要性分析方法，以及可直接复用的 Scikit-Learn / pandas 实践代码。

## 项目目标与二分类问题

客户流失（churn）指客户停止使用公司的服务。业务目标不是简单判断“谁已经流失”，而是利用历史客户数据学习规律，对当前客户输出一个流失概率，从而优先干预高风险客户。

这是典型的**二分类（Binary Classification）**问题：

$$
y_i \in \{0,1\}
$$

其中：

- $y_i=1$：正类（positive class），客户流失；
- $y_i=0$：负类（negative class），客户未流失；
- $x_i$：第 $i$ 个客户的特征向量；
- 模型 $g(x_i)$ 输出客户属于正类的概率。

可以写成：

$$
g(x_i) \approx y_i
$$

与只输出 0/1 标签相比，输出概率更有业务价值。例如：

$$
P(y=1 \mid x)=0.82
$$

表示模型认为该客户有约 82% 的流失概率。业务系统可以再根据阈值决定是否干预。

这个项目使用 Telco Customer Churn 数据集，每一行代表一个客户，特征大致包括：

- 人口属性：性别、是否老年人、是否有伴侣、是否有家属；
- 服务信息：电话、宽带、安全服务、技术支持、流媒体等；
- 合同与支付：合同类型、账单方式、支付方式；
- 数值特征：月费用、总费用、在网时长；
- 目标变量：`churn`。

---

## 完整机器学习流程

本项目可以概括为：

```text
原始数据
  ↓
数据清洗与类型转换
  ↓
Train / Validation / Test 划分
  ↓
EDA 与特征重要性分析
  ↓
类别特征 One-Hot Encoding
  ↓

  ↓
```

```python
df.columns = df.columns.str.lower().str.replace(' ', '_')
```

### 修复错误的数据类型

`totalcharges` 本应是数值，但原始数据被 pandas 识别为字符串。

先直接尝试：

```python
pd.to_numeric(df.totalcharges)
```

如果存在无法解析的值，会报错。

更实用的方式：

```python
tc = pd.to_numeric(
    df.totalcharges,
    errors='coerce'
)
```

`errors='coerce'` 会把无法解析的值转换成 `NaN`。

检查异常样本：

```python
df[tc.isnull()][
    ['customerid', 'totalcharges']
]
```

正式转换：

```python
df.totalcharges = pd.to_numeric(
    df.totalcharges,
    errors='coerce'
)

df.totalcharges = df.totalcharges.fillna(0)
```

这里课程采用 0 填补转换失败的值。

核心思路是：

```text
字符串列
   ↓
尝试转换数值
   ↓
非法值 → NaN
   ↓
再处理缺失值
```

## Train / Validation / Test

### 为什么需要三个数据集

老生常谈，三个数据集职责不同：

#### Training Set

用于拟合模型参数：

$$
w_0,w_1,\ldots,w_n
$$

#### Validation Set

用于：

- 比较模型；
- 选择特征；
- 选择超参数；
- 选择分类阈值；
- 判断是否过拟合。

#### Test Set

用于所有实验完成后的**最终泛化能力评估**。

测试集不应该参与模型设计。

---

### 60 / 20 / 20 划分

使用：

```python
from sklearn.model_selection import train_test_split
```

第一步，留下 20% 测试集：

```python
df_full_train, df_test = train_test_split(
    df,
    test_size=0.2,
    random_state=1
)
```

此时：

```text
full_train = 80%
test       = 20%
```

第二步，从 `full_train` 中再取 25%：

```python
df_train, df_val = train_test_split(
    df_full_train,
    test_size=0.25,
    random_state=1
)
```

因为：

$$
0.8 \times 0.25 = 0.2
$$

最终：

```text
train      = 60%
validation = 20%
test       = 20%
```

---

### random_state

```python
random_state=1
```

用于固定随机种子，使每次运行得到相同的数据划分。

如果不固定随机种子，每次重新运行代码都可能产生不同的训练集和验证集，从而使实验结果难以复现。

---

### 重置索引

`train_test_split` 会保留原数据的索引，因此通常需要：

```python
df_train = df_train.reset_index(drop=True)
df_val = df_val.reset_index(drop=True)
df_test = df_test.reset_index(drop=True)
```

`drop=True` 表示不把旧索引保存为新列。

---

### 分离目标变量

```python
y_train = df_train.churn.values
y_val = df_val.churn.values
y_test = df_test.churn.values
```

然后删除训练数据中的目标列：

```python

del df_val['churn']
del df_test['churn']
```

这是为了防止：

> **Target Leakage：把答案本身作为模型输入。**

`df_full_train` 可以暂时保留 `churn`，因为后续 EDA 和特征重要性分析需要它。

## 目标变量：Churn Rate

如果 `churn` 是 0/1：

```python
df_full_train.churn.value_counts(normalize=True)
```

可以查看比例。

更直接：

```python
global_churn = df_full_train.churn.mean()
```

因为二元变量：

$$
y_i \in \{0,1\}
$$

所以：

$$
\bar y
=
\frac{1}{n}\sum_{i=1}^{n}y_i
=
\frac{\text{正类数量}}{\text{样本总数}}
$$

因此 0/1 变量的均值就是正类比例。

本数据中：

```text
global churn ≈ 0.27
```

即约 27% 的客户流失。

这个性质很常用：

```python
binary_column.mean()
```

就可以直接得到事件发生率。

---

## 类别特征的重要性：Churn Rate 与 Risk Ratio

### 分组流失率

例如比较不同性别：

```python
churn_female = (
    df_full_train[
        df_full_train.gender == 'female'
    ]
    .churn
    .mean()
)

churn_male = (
    df_full_train[
        df_full_train.gender == 'male'
    ]
    .churn
    .mean()
)
```

与全局流失率比较：

```python
global_churn - churn_female
global_churn - churn_male
```

如果差值接近 0，说明该组的流失率和总体几乎一样，该特征可能没有太强区分能力。

---

### Difference

可以定义：

$$
Difference
=
GlobalRate-GroupRate
$$

解释：

- 接近 0：该组和总体差别小；
- 正值：该组流失率低于总体；
- 负值：该组流失率高于总体；
- 绝对值越大：该类别与总体差异越明显。

---

### Risk Ratio

相对风险定义为：

$$
Risk
=
\frac{GroupRate}{GlobalRate}
$$

解释：

$$
Risk = 1
$$

表示与总体风险相同。

$$
Risk > 1
$$

表示该组更容易流失。

$$
Risk < 1
$$

表示该组更不容易流失。

例如：

```python
churn_no_partner / global_churn
```

若结果：

```text
1.22
```

意味着该组流失率约为总体的 1.22 倍。

---

### 使用 groupby 批量分析

实际项目中不应该逐组手写：

```python
for c in categorical:
    df_group = (
        df_full_train
        .groupby(c)
        .churn
        .agg(['mean', 'count'])
    )

    df_group['diff'] = (
        df_group['mean'] - global_churn
    )

    df_group['risk'] = (
        df_group['mean'] / global_churn
    )

    display(df_group)
```

这里：

```python
.groupby(c)
```

按类别分组；

```python
.churn.agg(['mean', 'count'])
```

同时计算：

- `mean`：该组流失率；
- `count`：该组样本数。

样本数也非常重要，因为一个风险率很高但只有极少样本的类别，结论可能不稳定。

## 类别特征的重要性：Mutual Information

### 直觉

Risk Ratio 适合回答：

> 某个具体类别的风险比总体高多少？

但它不方便直接给“整个变量”打一个统一的重要性分数。

互信息（Mutual Information, MI）回答：

> 知道变量 $X$ 后，我们对变量 $Y$ 多知道了多少信息？

在本项目中：

> 知道某个客户特征之后，对是否流失的“不确定性”减少了多少？

如果一个特征和 churn 完全无关：

$$
MI(X,Y)=0
$$

信息越强，互信息越大。

互信息是对称的：

$$
MI(X,Y)=MI(Y,X)
$$

---

### 使用 mutual_info_score

```python
from sklearn.metrics import mutual_info_score
```

例如：

```python
mutual_info_score(
    df_full_train.contract,
    df_full_train.churn
)
```

---

### 批量计算类别特征互信息

先封装：

```python
def mutual_info_churn_score(series):
    return mutual_info_score(
        series,
        df_full_train.churn

```

然后：

```python
mi = (
    df_full_train[categorical]

mi.sort_values(ascending=False)
```

排名较高，而：

```text

```

互信息很低。

因此互信息非常适合：

> 对多个类别特征做统一的重要性排序。

## 数值特征的重要性：Correlation

### Pearson 相关系数

数值变量可以使用 Pearson correlation：

$$
r \in [-1,1]
$$

解释：

- $r \approx 1$：强正相关；
- $r \approx -1$：强负相关；
- $r \approx 0$：线性相关性弱。

对于 churn 这种 0/1 目标：

- 正相关：数值越大，流失倾向越高；
- 负相关：数值越大，流失倾向越低。

课程中给出的粗略强度划分：

```text
|r| < 0.2      → low
0.2 ≤ |r| < 0.5 → medium
0.5 ≤ |r|       → strong
```

这只是经验性的解释尺度，不是普适统计定律。

---

### pandas 计算方法

$$

在网时间越长，越不容易流失。

#### monthlycharges

$$
r \approx 0.20
$$

月费越高，流失倾向略高。

#### totalcharges

$$
r \approx -0.20
$$

总费用较高往往也意味着客户已经使用服务较长时间，因此表现为负相关。

# 特征编码与逻辑回归

## One-Hot Encoding

### 为什么类别特征需要编码

线性模型本质上计算：

$$
w_0+w_1x_1+\cdots+w_nx_n
$$

因此输入必须是数值。

例如：

```text
contract = two_year
```

不能直接与权重相乘。

---

### One-Hot Encoding 原理

假设：

```text
contract ∈ {
    month-to-month,
    one_year,
    two_year
}
```

可以展开成：

```text
contract=month-to-month
contract=one_year
contract=two_year
```

如果某客户：

```text
contract = two_year
```

编码为：

```text
0 0 1
```

每个类别对应一个二元特征。

---

### DataFrame 转字典

`DictVectorizer` 使用：

```python
[
    {...},
    {...},
    {...}
]
```

这种“每行一个字典”的结构。

转换：

```python
train_dict = (
    df_train[categorical + numerical]
    .to_dict(orient='records')
)
```

---

### DictVectorizer

```python
from sklearn.feature_extraction import DictVectorizer

dv = DictVectorizer(sparse=False)

X_train = dv.fit_transform(train_dict)
```

`fit_transform()` 实际执行两个步骤：

```text
fit
  ↓
学习有哪些字段和类别

transform
  ↓
把样本转换成数值矩阵
```

查看生成的特征：

```python
dv.get_feature_names_out()
```

---

### Validation 只能 transform

训练集：

```python
X_train = dv.fit_transform(train_dict)
```

验证集：

```python
val_dict = (
    df_val[categorical + numerical]
    .to_dict(orient='records')
)

X_val = dv.transform(val_dict)
```

不能重新：

```python
dv.fit_transform(val_dict)
```

原因是验证数据不能参与定义特征空间。

正确原则：

> **所有 preprocessing 的 fit 都只发生在训练数据上；其他数据只 transform。**

这个原则适用于：

- One-Hot Encoding；
- StandardScaler；
- 缺失值统计量；
- PCA；
- 特征选择；
- 其他需要从数据中“学习参数”的预处理器。

## Logistic Regression 理论

### 从线性回归开始

线性模型先计算一个 score：

$$
z
=
w_0+w_1x_1+w_2x_2+\cdots+w_nx_n
$$

向量形式：

$$
z=w_0+w^Tx
$$

线性回归直接把 $z$ 当预测结果。

问题是：

$$
z\in(-\infty,+\infty)
$$

但概率必须满足：

$$
p\in[0,1]
$$

因此逻辑回归再对线性 score 使用 sigmoid。

---

### Sigmoid

$$
\sigma(z)
=
\frac{1}{1+e^{-z}}
$$

逻辑回归：

$$
P(y=1\mid x)
=
\sigma(w_0+w^Tx)
$$

也就是：

$$
P(y=1\mid x)
=
\frac{1}
{1+\exp(-(w_0+w^Tx))}
$$

Sigmoid 把任意实数映射到：

$$
(0,1)
$$

---

### Sigmoid 的重要性质

#### 当 $z=0$

$$
\sigma(0)=0.5
$$

所以：

```text
score > 0 → probability > 0.5
score < 0 → probability < 0.5
```

#### 当 $z\to+\infty$

$$
\sigma(z)\to1
$$

#### 当 $z\to-\infty$

$$
\sigma(z)\to0
$$

---

### NumPy 实现

```python
def sigmoid(z):
    return 1 / (1 + np.exp(-z))
```

绘制：

```python
z = np.linspace(-7, 7, 51)

plt.plot(z, sigmoid(z))
```

---

### 手写逻辑回归预测过程

```python
def logistic_regression(xi):
    score = w0

    for j in range(len(w)):
        score = score + xi[j] * w[j]

    result = sigmoid(score)

    return result
```

本质就是：

```text
线性组合
   ↓
Sigmoid
   ↓
概率
```

因此 Logistic Regression 虽然名字叫“Regression”，实际是经典分类算法。

## 概率预测与分类阈值

### predict 与 predict_proba

硬分类：

```python

```

直接返回：

```text

1
```

概率预测：

```python
model.predict_proba(X_val)
```

```text

```

例如：

```text

```

$$
P(y=0)+P(y=1)=1
$$

```python

```

这里：

```python
[:, 1]
```

表示：

```text
所有行
第 2 列
```

即正类概率。

### 自定义阈值

默认可以选择：

$$
threshold=0.5
$$

代码：

```python
churn_decision = (y_pred >= 0.5)
```

得到布尔数组：

```text

False
...
```

也可以转换为整数：

```python
churn_decision.astype(int)
```

阈值不是逻辑回归模型本身的一部分。

模型输出概率：

$$
P(y=1\mid x)
$$

而：

```text
probability → 0/1
```

是后续决策规则。

$$

=

NumPy / pandas 可以直接利用布尔值均值：

```python

```

## Logistic Regression 参数解释

### 将特征名与权重对应

模型参数：

```python
model.coef_[0]
```

只有数字，不知道对应哪一列。

使用：

```python
dict(
    zip(
        dv.get_feature_names_out(),
        model.coef_[0].round(3)
    )
)
```

即可得到：

```text
feature → weight
```

例如：

```text
contract=month-to-month    +0.475
contract=two_year          -0.408
internetservice=fiber_optic +0.316
tenure                     -0.070
```

---

### 权重方向

逻辑回归先计算：

$$
z=w_0+\sum_j w_jx_j
$$

然后：

$$
p=\sigma(z)
$$

由于 sigmoid 单调递增：

- $w_j>0$：该特征会把 score 推高，从而增加预测概率；
- $w_j<0$：把 score 压低，从而降低预测概率。

但需要注意：

> 权重不是简单的“单变量相关性”，它是在其他特征同时存在时得到的模型参数。

如果特征高度相关，单独解释某个权重需要谨慎。

---

## One-Hot 特征如何进入模型

假设：

```text
contract=month-to-month
contract=one_year
contract=two_year
```

一个客户只能属于一个合同类型。

如果客户是 `two_year`：

```text
0, 0, 1
```

那么合同部分对 score 的贡献：

$$
0\cdot w_{month}
+
0\cdot w_{one}
+
1\cdot w_{two}
=
w_{two}
$$

所以每个样本只会激活对应类别的权重。

---

# 核心知识与实践经验

## 核心知识总结

### 二分类

目标：

$$
y\in\{0,1\}
$$

模型通常输出：

$$
P(y=1\mid x)
$$

而不是只输出类别。

---

### 二元变量均值

如果：

$$
y\in\{0,1\}
$$

那么：

$$
E[y]
$$

就是正类比例。

因此：

```python
df.churn.mean()
```

就是 churn rate。

---

### 类别特征重要性

可以从三个层面理解：

#### Group Churn Rate

观察每个类别的实际流失比例。

#### Risk Ratio

$$
Risk
=
\frac{GroupRate}{GlobalRate}
$$

适合解释具体类别相对总体的风险。

#### Mutual Information

$$
MI(X,Y)
$$

适合把完整类别变量压缩成一个重要性分数，并在不同类别特征之间比较。

---

### 数值特征重要性

Pearson correlation：

$$
r\in[-1,1]
$$

符号表示方向：

```text
+ → 同向
- → 反向
```

绝对值表示线性关系强度。

---

### One-Hot Encoding

把：

```text
category = A/B/C
```

转换成：

```text
category=A
category=B
category=C
```

使类别变量能够进入线性模型。

---

### fit 与 transform

最重要的实践原则之一：

```text
Train:
    fit + transform

Validation/Test/New Data:
    transform only
```

任何会从数据中“学东西”的预处理，都必须遵守这个原则。

---

### Logistic Regression

先计算：

$$
z=w_0+w^Tx
$$

再通过：

$$
\sigma(z)
=
\frac{1}{1+e^{-z}}
$$

得到：

$$
P(y=1\mid x)
$$

所以可以把逻辑回归理解为：

> **线性模型 + Sigmoid。**

---

### 权重解释

由于 sigmoid 单调递增：

```text
weight > 0
→ score 增加
→ 正类概率增加

weight < 0
→ score 减少
→ 正类概率降低
```

但在多变量模型中，权重表示的是：

> 在其他特征共同进入模型条件下，该特征对线性 score 的影响。

---

### 概率与决策是两层

模型负责：

```text
x → probability
```

业务规则负责：

```text
probability → decision
```

例如：

```python
probability >= 0.5
```

才转换成类别 1。

所以阈值可以根据业务需求调整，而不需要重新训练模型。

---

## 实践经验

1. **先明确变量语义，再看 dtype。**  
   `seniorcitizen` 虽然是 0/1，但本质仍然是类别变量。

2. **训练集与验证/测试集的 preprocessing 必须隔离。**  
   `fit` 只对训练数据执行，验证和测试只 `transform`。

3. **测试集不是第二个验证集。**  
   不要反复查看测试集结果后继续调整模型。

4. **特征重要性方法要与变量类型匹配。**  
   类别变量可以用 risk ratio、mutual information；数值变量可以先看 correlation。

5. **相关性不等于因果性。**  
   `tenure` 与 churn 负相关，只说明数据中它们存在统计关系，不能单凭相关系数推出因果机制。

6. **模型参数与业务决策应分开。**  
   Logistic Regression 输出概率；0.5 只是一个决策阈值。

7. **编码器与模型必须作为同一套 preprocessing pipeline 保存和使用。**  
   生产预测不能重新 fit 一个新的编码器。

8. **Validation 和 Test 表现接近是好现象。**  
   本项目约 80.3% vs 81.5%，说明最终测试表现与验证阶段一致。

9. **Accuracy 不是分类问题的全部。**  
   尤其在类别不平衡任务中，还需要进一步学习 confusion matrix、precision、recall、F1、ROC AUC 和阈值选择。

10. **这套流程可以直接迁移到其他二分类任务。**  
    例如：
    
    - 信用违约预测；
    - 垃圾邮件检测；
    - Lead scoring；
    - 用户流失预测；
    - 风险预警。

---

## 一句话复盘

这章最重要的不是记住 Telco 数据本身，而是掌握一条可复用的分类建模链路：

```text
清洗数据
→ 正确划分 Train/Val/Test
→ 用 EDA 和统计量理解特征
→ 对类别变量编码
→ Logistic Regression 输出概率
→ Validation 做实验
→ Full Train 重训
→ Test 做最终评估
→ 保存 preprocessing + model 用于预测
```
